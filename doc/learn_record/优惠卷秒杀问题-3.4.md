# 解决的问题：黑马点评的秒杀模块

## 目标：超卖问题（秒杀不能超卖）、同一个用户只能买一次、支持高并发

## 一、超卖问题

高并发下可能出现

```
库存 = 1
两个线程同时判断库存 > 0
都去扣减
最终库存 = -1
```

## 解决办法：原子SQL+乐观锁（注意乐观锁与悲观锁）

```
.setSql("stock = stock - 1")
.eq("voucher_id", voucherId)
.gt("stock", 0)
.update();
//把“判断 + 修改”合并成一条 SQL，数据库保证原子性，本质是数据库级 CAS，利用 where stock > 0 作为条件控制
```

## 二、解决一人一单问题

```
int count = query()
    .eq("user_id", userId)
    .eq("voucher_id", voucherId)
    .count();
```

```
if(count > 0){
    return Result.fail("用户已经购买过一次！");
}
```

新问题：并发下重复下单

```
线程A 查 count=0
线程B 查 count=0
线程A 插入
线程B 插入
//最后同一个用户两条订单，原因：查询+判断+插入不是原子操作
```

```
乐观锁比较适合更新数据，而现在是插入数据，所以我们需要使用悲观锁操作
```



## 2.1、加锁解决一人一单

```
synchronized(userId.toString().intern()){
	//查询订单、扣减库存
	}
//userId.toString() 每次 new 新对象，锁对象不同，ntern() 从字符串常量池取唯一对象
```

## 2.2 加锁后出现事务问题

```Java
@Transactional
public  Result createVoucherOrder(Long voucherId) {
 Long userId = UserHolder.getUser().getId();
 synchronized(userId.toString().intern()){
         // 5.1.查询订单
        int count = query().eq("user_id", userId).eq("voucher_id", voucherId).count();
        // 5.2.判断是否存在
        if (count > 0) {
            // 用户已经购买过了
            return Result.fail("用户已经购买过一次！");
        }

        // 6.扣减库存
        boolean success = seckillVoucherService.update()
                .setSql("stock = stock - 1") // set stock = stock - 1
                .eq("voucher_id", voucherId).gt("stock", 0) // where id = ? and stock > 0
                .update();
        if (!success) {
            // 扣减失败
            return Result.fail("库存不足！");
        }

        // 7.创建订单
        VoucherOrder voucherOrder = new VoucherOrder();
        // 7.1.订单id
        long orderId = redisIdWorker.nextId("order");
        voucherOrder.setId(orderId);
        // 7.2.用户id
        voucherOrder.setUserId(userId);
        // 7.3.代金券id
        voucherOrder.setVoucherId(voucherId);
        save(voucherOrder);

        // 7.返回订单id
        return Result.ok(orderId);
    }
}
```

### 出现的问题

线程A：

```
save()
释放锁
事务未提交
```

线程B：

```
拿到锁
查询数据库
看不到线程A的数据（事务未提交）
再次插入
```

❌ 又重复下单

### 原因分析

Spring 事务基于 AOP 代理。

- 事务管理：我们前面所讲解的Spring事务管理，底层其实也是通过AOP来实现的，只要添加@Transactional注解之后，AOP程序自动会在原始方法运行前先来开启事务，在原始方法运行完毕之后提交或回滚事务

事务提交发生在：

```
方法执行结束之后
```

而锁是在：

```
synchronized 块结束时释放
```

锁生命周期 < 事务生命周期

### 解决方案

```
public Result seckillVoucher() {

    synchronized (...) {

        return this.createVoucherOrder();
    }
}

@Transactional
public Result createVoucherOrder() {
}
```

## 2.3 出现事务生效问题

```
this.createVoucherOrder()
```

事务不生效。

### 原因：Spring 事务基于代理。内部调用不会经过代理。

### 正确方式：

```

        synchronized (...) {
        //获取代理对象（事务）
        //注意代理对象是接口类型
			IVoucherOrderService proxy = (IVoucherOrderService) AopContext.currentProxy();
        return proxy.createVoucherOrder(voucherId);
    }
```

并开启：

```
@EnableAspectJAutoProxy(exposeProxy = true)
```

## 三、集群环境下的并发问题

单机环境

```
服务器A
  └─ Tomcat
      └─ JVM
          ├─ 线程1
          └─ 线程2
//所有线程在同一个 JVM 内，字符串常量池在同一个 JVM 内，intern() 得到的是同一个对象
```

集群环境下

JVM1 有自己的字符串常量池，JVM2 有自己的字符串常量池

**synchronized 只能保证 JVM 内线程安全，无法保证多 JVM 之间的互斥。**
